## 1. 设计定位与寄存器判断

### 1.1 寄存器
- **Product Register**：产品型设计。本平台是 7×24 小时值守的能源管理工具，核心目标是“让值班人员在 3 秒内定位异常并决策”。设计标杆是“赢得熟悉感”——像医院监护仪、航空雷达、潜艇控制面板一样，第一眼就知道哪里需要关注。
- **平台轴**：Web 大屏（4K 拼接屏优先）+ 后台管理页（PC 办公）。

### 1.2 三个可调轴
| 参数 | 值 | 说明 |
|------|---|------|
| `DESIGN_VARIANCE` | 5 | 整体居中对齐的指挥舱布局，但左右数据面板不对称、底部趋势条独立成区，避免呆板。 |
| `MOTION_INTENSITY` | 6 | 实时数据脉冲、趋势图刷新、告警闪烁等功能性动效；禁止无意义的粒子流/霓虹装饰。 |
| `VISUAL_DENSITY` | 7 | 高信息密度（值班场景），但用 1px 边框、卡片分组、留白槽将信息分块到 ≤4 个视觉组。 |

### 1.3 品牌声音词（物理对象）
**精密 · 沉静 · 可控 · 实时**  
对应物理对象：夜间 ICU 监护仪、机场塔台雷达、深海潜艇操控台。

## 2. 对标产品分析（≥3 个）

### 2.1 Advantech WISE-IoT iEMS / 花莲门诺医院智慧管理平台
- **对标点**：医院建筑群能源管理 + BIM/3D 可视化 + 多院区远程监控。
- **设计语言**：深色底、蓝色/青色强调、设备状态色块、3D 模型告警高亮。
- **可借鉴**：将“设备异常”直接定位到 3D 模型具体点位；按建筑维度组织数据。
- **需避免**：部分界面信息层级不够清晰，告警与正常状态颜色过于接近。

### 2.2 智碳能源管理系统（zhitan-ems，开源 EMS）
- **对标点**：能源总览驾驶舱、实时监测、分项能耗、智能告警、深色/浅色双主题。
- **设计语言**：卡片化 KPI、ECharts 图表、标签页切换、状态色统一。
- **可借鉴**：后台管理列表页的信息密度与筛选模式；尖峰平谷、能耗对比的图表类型。
- **需避免**：默认界面偏“后台工具感”，缺少大屏沉浸感；图标风格不统一。

### 2.3 腾讯智慧园区 / 智慧光伏储能数字孪生大屏
- **对标点**：数字孪生园区、3D 场景 + 左右面板、源网荷储一体化、光储充可视化。
- **设计语言**：大面积 3D 场景、左右非对称数据面板、顶部全局指标、底部趋势。
- **可借鉴**：3D 模型作为视觉中心，面板作为信息卫星区；楼栋/设备 drill-down 交互。
- **需避免**：过度使用发光边框和科幻装饰线，容易视觉疲劳。

### 2.4 数维图 Sovit3D 智慧医院可视化
- **对标点**：Web3D 医院园区、楼栋切换、设备点位、环境/安防/能耗多系统联动。
- **设计语言**：3D 园区鸟瞰、系统色区分、弹窗详情、楼层内景。
- **可借鉴**：楼栋切换面板、设备弹窗详情、子系统颜色编码。
- **需避免**：部分模板使用紫色→粉色渐变作为主视觉，本项目明确禁用。

## 3. 设计语言与情绪板

### 3.1 关键词
- **精密（Precision）**：等宽数字、对齐的 KPI 卡片、清晰的阈值线。
- **沉静（Calm）**：深蓝灰背景、低饱和边框、克制的发光。
- **可控（Controllable）**：明显的状态色、一键定位、可开关的实时模式。
- **实时（Real-time）**：数据脉冲、时间戳、最后刷新倒计时。

### 3.2 情绪板意象
- 深夜 ICU 多参数监护仪：数据在深色背景上以高对比度跳动。
- 机场塔台雷达屏：中心地图，周边环状信息，异常以高饱和色闪烁。
- 潜艇声呐控制台：沉静蓝绿，仅在需要时亮起。

### 3.3 与现有截图的关系
- 保留：3D 医院模型居中、左右数据面板、顶部标题与导航、深色指挥舱氛围。
- 升级：用 Design Token 替换硬编码色值；用 SVG 图标替换 Font Awesome/emoji；用更克制的光效替换高饱和发光；引入子系统色编码与楼栋联动。

## 6.4 双联动顶部菜单（MVP 锚点 · 核心交互）

> 本项目相对参考工程的核心差异：参考工程顶部仅有“子系统”导航；本平台顶部需**同时联动楼栋（1–10）与子系统（7）+ 全院总览**，两者正交组合，全局状态由 `sceneStore`（`selectedBuilding`、`activeSubsystem`）维护，大屏/后台/设备详情共享。

### 6.4.1 菜单结构
```
顶部 Header
├─ 左：实时时钟（日期 / 时间 / 星期）
├─ 中：平台标题
│     ├─ 一级：楼栋选择器（横向 10 个楼栋胶囊 + “全院总览”）
│     │     1号楼·120急救 │ 2号楼·门诊 │ 3号楼·住院 │ … │ 10号楼·宿舍 │ [全院总览]
│     └─ 二级：子系统页签（7 个，选中楼栋后联动过滤；全院总览时显示全部）
│           能源一体化 │ 设备生命周期 │ 空调 │ 照明 │ 电力 │ 热水 │ 电梯
└─ 右：实时模式开关 │ 主题 │ 天气 │ 用户
```

### 6.4.2 交互规则
- **楼栋选择**：点击某楼栋胶囊 → `selectedBuilding` 置为该楼；3D 镜头飞向该楼（`building_anchor`），左右面板过滤为该楼数据，子系统页签保持当前选择或重置为“全部”。
- **子系统切换**：点击子系统页签 → `activeSubsystem` 置为该子系统；中央 3D 仅高亮该子系统设备点位，其余半透明；右侧面板切换为该子系统指标；顶部标题动态为“{楼栋名} · {子系统名}”或“全院 · {子系统名}”。
- **全院总览**：点击“全院总览” → `selectedBuilding = null`；展示全院一张图，子系统页签作为维度筛选（不锁定楼栋）。
- **正交组合**：楼栋 × 子系统任意组合均有效，状态共享；切换任一维度，大屏/面板/设备详情全部联动刷新（含 URL 路由 `/bigscreen/:building?/:subsystem?`）。
- **当前位置指示**：楼栋胶囊与子系统页签均用 `--kp-accent` 底部指示条 + 文字高亮，激活态加微光（`--kp-elev-glow`）。

### 6.4.3 视觉规格
- 楼栋胶囊：高度 36px、圆角 `--kp-radius-pill`、未选中 `bg: transparent` + `--kp-border`；选中 `bg: var(--kp-glow-soft)` + `--kp-accent` 文字 + 底部 2px 指示条。
- 子系统页签：高度 40px、图标 20px（lucide）+ 文字 14px（`--kp-text-md`、字距 `0.04em`）；未选中 `--kp-fg-muted`，选中 `--kp-accent` + 图标 drop-shadow glow。
- 楼栋胶囊内可显示该楼状态点（绿/黄/红），不额外占用宽度。


### 6.5.2 5 种界面模式统一视觉语言
| 模式 | 载体 | 视觉一致性要点 |
|------|------|----------------|
| 全景主界面 | 大屏 / 后台首页 | 同 Header + 3D 视口；无选中楼栋时为全院一张图 |
| 数据大屏总览 | `/bigscreen` | 上述骨架；双联动菜单驱动 |
| 功能操作后台 | `/admin` | 浅色或深色 Sidebar + 表格；复用同一 Token、同一图标库、同一状态色 |
| 设备详情 | 弹窗/抽屉 | 深色浮层（`--kp-elev-raised` + `backdrop-filter`）；参数网格 + 控制按钮 |
| 分级权限子界面 | 登录/权限受限 | 同设计语言；低权限隐藏高危控制按钮（非仅 disabled） |

### 6.5.3 真实文案（P0 禁用占位）
- 加载：`正在加载开平市中心医院能源数据…`
- 空态：`该院栋暂未接入 {子系统} 设备` / `暂无告警数据，运行状态正常`
- 错误：`能源数据获取失败，请稍后重试` + 重试按钮
- 离线：`实时连接已断开，正在显示最近缓存数据`

## 9. 关键页面设计提示词

### 9.1 页面：首页 / 综合态势大屏
- **路由**：`/bigscreen/overview`
- **布局**：
  - 顶部 Header：平台标题“开平市中心医院能源管理平台”，**双联动菜单（楼栋 1–10 + 全院总览 / 子系统 7）**，左侧实时时钟，右侧主题切换/实时模式/天气/用户。
  - 中央 3D 视口：加载 `hospital.glb`（Three.js/TresJS），默认鸟瞰角度，显示 10 栋楼位置标记；点位用模型局部坐标 `{x,y,z}` 放置（参考架构 ADR-001）。
  - 左侧面板（384px）：告警滚动列表（按严重级：严重/预警/正常，红/黄/绿）、今日能耗概览、设备在线率。
  - 右侧面板（384px）：7 大子系统快速指标（空调/照明/电力/热水/电梯/生命周期/综合能源），每个子系统一张 mini 卡片（带子系统色编码图标），点击联动 3D 视角。
  - 底部栏（176px）：能耗趋势（24h/7d/30d）、当前状态饼图、应急响应按钮、科室告警分布。
- **核心组件**：
  - `ThreeViewer`（TresJS）：3D 模型容器，支持鼠标旋转/缩放/复位，镜头飞行 `building_anchor`，子系统高亮。
  - `BuildingMarker`：楼栋标记点，带在线/告警/离线状态色环。
  - `AlarmScroller`：告警列表，自动滚动，严重告警红色闪烁，点击定位到设备。
  - `SubsystemCard`：子系统 mini 卡片，显示 2-3 个核心 KPI。
  - `TrendChart`：折线图，时间轴可切换。
- **交互**：
  - 点击楼栋标记 → 右侧子系统卡片过滤为该楼栋数据；3D 镜头推进到楼栋。
  - 点击顶部子系统导航 → 右侧展开该子系统详情；3D 中仅高亮相关设备。
  - 开启实时模式 → 数据每 3s 刷新，图表右侧实时追加数据点。
  - 点击告警项 → 3D 镜头飞行到故障设备，弹出设备详情弹窗。

  - 右侧：子系统指标面板，按子系统 Tab 切换（7 个 Tab）。

## 11. 动效与无障碍

### 11.1 动效规范
| 场景 | 时长 | 说明 |
|------|------|------|
| 按钮 hover | 150ms | 颜色、边框、阴影过渡 |
| 面板展开 | 200ms | 高度/透明度 |
| 弹窗进入/退出 | 250ms | scale + opacity |
| 3D 镜头飞行 | 400-600ms | cubic-bezier，避免眩晕 |
| 实时数据脉冲 | 1200ms loop | 仅用于“实时中”状态指示 |
| 告警闪烁 | 800ms loop | 严重告警卡片边框闪烁 |

所有动效必须响应 `prefers-reduced-motion: reduce`，此时禁用持续循环动画，改为静态色块或一次性的透明度变化。

### 11.2 无障碍
- 对比度：正文与背景 ≥ 4.5:1；大文字/图标 ≥ 3:1。
- 焦点环：所有可交互元素有 `:focus-visible` 的 `--kp-focus-ring`。
- 键盘导航：顶部导航、面板按钮、弹窗均可通过 Tab/Enter/Esc 操作。
- 图标按钮必须有 `aria-label`。
- 颜色不是唯一信息载体：告警同时有文字、图标、闪烁三种提示。
- 触摸目标：后台管理页按钮 ≥ 44×44px；大屏按钮 ≥ 48×48px。

## 12. Do's and Don'ts

### [√] Do
- 所有颜色通过 `--kp-*` Token 引用。
- 使用 `lucide-vue-next` 作为唯一图标库（ADR-002），尺寸 16/20/24px，语义覆盖 7 子系统 + 楼栋 + 设备类型。
- 每屏强调色 `#00E5FF` 使用不超过 2 处大面积。
- 3D 模型作为真实业务内容展示，不是抽象装饰。
- 数据使用真实业务字段（功率 kW、电量 kWh、温度 ℃、电流 A）。
- 控制操作根据权限禁用/隐藏。

### [×] Don't
- 不使用 emoji 作为功能图标。
- 不使用紫色到粉色的渐变作为主视觉。
- 不出现 “Welcome to”、“Lorem ipsum”、空口号。
- 不硬编码颜色值（允许的唯一例外：纯黑/纯白用于特殊遮罩）。
- 不用左侧彩色竖条作为卡片强调。
- 不用渐变文字（`background-clip: text`）。
- 不在 3D 场景上叠加无意义的粒子流或霓虹几何线。
- 卡片圆角不超过 16px。

# ADR-003: 数据源混合模式 — Connector 抽象 + 工厂 + 配置热切换

- 状态：Accepted（2026-08-17）
- 决策者：高见远（首席架构师）

## Background
需求：「数据先用模拟数据开发，但架构必须支持随时切换为真实接口（MQTT/Modbus/HTTP 等）的混合模式」。目标是在 MVP 阶段用模拟数据快速推进，后续在不改动前端、不停服的前提下灰度接入真实设备。

## Decision
定义统一数据源抽象 `Connector`：

```ts
interface Connector {
  connect(): Promise<void>;
  read(deviceId: string, keys: string[]): Promise<Metric[]>;
  subscribe(deviceId: string, cb: (m: Metric) => void): void;
  send(deviceId: string, cmd: ControlCommand): Promise<Ack>;
}
interface Metric { time: Date; device_id: string; metric_key: string; value: number; unit: string; quality: 'good'|'bad'|'uncertain'; source: 'mock'|'real'; }
```

实现：
- `MockConnector`：按 `device_categories.default_metrics` 生成合成时序（随机游走 + 昼夜曲线 + 偶发故障）。
- `MqttConnector` / `ModbusConnector` / `HttpConnector`：各自 `normalize(raw)` 映射到统一 `Metric`。
- `ConnectorFactory`：依据 `connector_configs` 表（`source_mode / endpoint / topic / register_map / poll_interval`）实例化。
- 全局开关 `DATA_SOURCE_MODE=mock|real`；支持按设备/楼栋/子系统粒度覆盖（灰度切真实）。
- 切换热加载，无需重启；前端仅消费 `/api/v1/*` 与 WS，零感知。

## Consequences
正面：
- 前端与数据源完全解耦，模拟/真实切换无前端改动。
- 灰度接入真实设备（单楼/单系统先行），降低对接风险。
- 统一 Metric 模型，真实与模拟数据可同屏对比（source 字段标识可信度）。

负面：
- 需维护归一化层与各协议适配器（MVP 阶段 Mock 为主，Real 待甲方协议文档）。

## Alternatives
- 前端直连设备/网关：破坏分层、无法统一切换，拒绝。
- 双套前端（mock 版/real 版）：维护灾难，拒绝。

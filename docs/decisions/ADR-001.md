# ADR-001: 3D 渲染引擎选型 — Three.js（TresJS）替代 Cesium

- 状态：Accepted（2026-08-17）
- 决策者：高见远（首席架构师）

## Background
参考项目 `D:\wwwroot\all\bigscreen` 使用 Cesium（地理球 + 高德底图 + 经纬度场景配置 `haibing.json`）渲染 `hospital.glb`。本次需求明确「技术栈另选，要求扩展性强」，且目标是一个封闭院区数字孪生大屏，并非地理分布系统。Cesium 的地球/在线底图对院区场景属于过重依赖，且经纬度坐标下精确放置上千设备点位困难、场景配置（haibing.json）与业务解耦弱。

## Decision
采用 **Three.js** 作为 3D 渲染引擎，以 **@tresjs/core + @tresjs/cientos** 提供 Vue3 声明式场景图封装（保留团队 Vue3 技术栈）；复杂自定义图元/着色器可降级到原生 three 在自定义组件中实现。

- 设备点位以「模型局部坐标 `{x,y,z}`」存储于 `device_points.position`，避免经纬度偏差。
- 模型文件通过后端 `scene_configs.model_url` 配置加载（默认 `/resources/models/hospital.glb`），支持后台热替换。
- 场景配置由后端 `scene_configs` + `/api/v1/scene/*` 提供，替代前端硬编码 `haibing.json`。

## Consequences
正面：
- 包体更轻、加载更快，契合合同「模型秒加载、运行无卡顿」。
- 局部坐标放置设备点位精度高，扩展热力图/标注/后处理生态成熟。
- 声明式场景图提升可维护性，与 Vue3 一致。

负面：
- 失去 Cesium 的在线地理底图/经纬度上下文（院区封闭场景不需要）。
- 需重写参考项目的 3D 部分（约 1 个模块工作量），已评估可行。

## Alternatives
- 保留 Cesium（参考栈）：地理能力强但与院区场景错配、配置笨重，评分 21 < 23，未采用。
- React + Three.js：与团队 Vue 栈不一致，评分 20，未采用。

# 阶段五交付说明 — 管理后台完善 + 大屏一屏化

> 日期：2026-08-17
> 基于：阶段四（全量模拟数据 + 后台 CRUD + 计费/历史/告警/报表）
> 状态：已验证（后端 5168 + 前端 5169 在线）

## 一、管理后台完善（对应需求 1–8）

### 1. 设备管理
- 改为「设备台账 / 设备类型 / 设备品牌」三个页签。
- **设备台账**：新增「序号」列 `(页-1)*每页+行号+1`。
- **设备类型**：序号 / 名称 / 描述 / 操作(编辑·删除)，默认预置 10 类（分体机空调、多联机空调、空气能热泵热水机组、水泵、冷却塔、中央空调主机、照明灯具、配电柜、电梯、UPS电源），可自定义增改删。
- **设备品牌**：序号 / 品牌名称 / 描述 / 操作，默认预置 10 个（格力、美的、海尔、约克、特灵、大金、施耐德、西门子、飞利浦、松下）。

### 2. 角色管理并入用户管理
- 用户管理页内新增「角色」页签：序号 / 编码 / 名称 / 权限 / 描述 / 操作。
- 后端预置 4 个默认角色并配置权限：**系统管理员(全权限)、运维工程师、医院后勤/能源管理值班人员、院领导**。

### 3. 告警异常配置并入告警管理
- 告警管理页内新增「异常配置」页签（事件代码/名称/描述/通知/告警/级别/阈值/恢复阈值），与告警列表同页。

### 4. 楼栋子系统配置 — 名称可自定义
- 楼栋名称：行内编辑，落库 `buildingCrudApi.update`。
- 子系统显示名：每行可编辑，落库 `subsystemLabelApi`（持久化覆盖，默认取 7 子系统原名）。

### 5. 监控运维（全新模块，5 个页签）
- **实时监控**：按楼栋/设备查看，设备实时指标；远程开关机；空调「还原遥控器」（模式/设定温度16–30/风速）；联动计费电价 + 配额设置（可改配额）。
- **实时告警**：按告警级别 / 设备名称 / 设备类型 / 所属区域(楼栋) 过滤查询，确认/清除，一键跳转该设备远程控制。
- **群组控制**：群组增改删（选楼栋+选设备），批量 开机/关机/遥控/电源 动作。
- **工单管理**：工单增改删（标题/描述/指派/楼栋/产品类型/设备/状态）。
- **我的代办**：工单统计卡（总数/处理中/反馈/未完成/已完成/关闭）+ 按状态列表。

### 6. 菜单合并
- 顶层菜单收敛为：楼栋子系统配置 / 设备管理 / 用户管理(含角色) / 告警管理(含异常配置) / 监控运维 / 计费管理 / 历史数据 / 能耗报表(含报表导出) / 楼栋管理 / 场景模型 / 操作日志。（独立「角色管理」「告警异常配置」「报表导出」已从菜单移除，报表导出并入能耗报表页签。）

### 7. 左侧菜单自定义排序
- 菜单支持拖拽 / 上下箭头排序，顺序持久化 `menuOrderApi`（后端 `menus/order` 落盘）。

### 8. 样式优化（admin.css）
- 文本/背景对比度提升（主文本用 `--kp-fg`）；列间细线 + `|` 文字分隔符；行底虚线分隔；表格奇偶斑马纹。深蓝指挥舱主题、lucide 图标、无 emoji、无紫粉渐变。

## 二、前端大屏（对应需求 1–2）
- **一屏自适应**：固定 1920×1080 舞台，按窗口尺寸 `scale = min(vw/1920, vh/1080)` 整体缩放，任意分辨率（1080p/2K/4K）一屏完整显示无滚动条。
- **布局**：顶栏(标题+GIS定位+实时时钟+楼栋/子系统选择器) / 左列面板 / 中列3D模型+底部趋势 / 右列KPI与图表。
- **模型+菜单+数据联动**：顶栏选楼/选子系统 → `sceneStore` → `bigscreenApi.panels` 重新拉取(15s轮询) + 3D 楼栋高亮/相机飞行/设备点过滤 + hospital.glb 模型居中加载（失败回退真实模型再回退占位）。
- 参考 `D:\wwwroot\all\bigscreen` 的视觉语言（四角装饰、斜切标题、stat-grid、echarts、数字翻滚），沿用本项目暗蓝 token。

## 五、两点说明
1. **`runtime.json` 沙箱锁**：该文件被本沙箱 EPERM 锁定（删/写均拒，仅运行中的 node 可写）。Phase-4 残留的 2 个角色（运维操作员/只读访客）会随种子合并显示，属无害演示数据；生产切 Postgres 后无此问题。
2. **生产 `npm run build` 环境限制**：本沙箱禁止把 69MB 的 `public/models/hospital.glb` 拷贝进 `dist/`，故生产构建在这一环境会报 EPERM（仅影响构建产物复制，非代码问题）。演示使用的是 5169 dev server（已正常服务）；在普通机器上 `npm run build` 可正常通过。如需我调整 vite 配置以规避该拷贝，可告知。

# 开平中心医院能源管理平台 —— 七子系统差距分析（GK-25 附）

> 与 `seven-subsystems-roadmap.md` 配套。本文件从"用户期望 vs 当前实现"视角，按 7 个子系统逐节给出：用户要什么 / 现在有什么 / 差在哪 / 最关键的 3 个补齐动作。
> 数据判定依据：通读 `backend/src/`（controller/service/connector/synthetic.aggregate）与 `docs/architecture/game-engine-refactor-status.md`。

---

## 1. 智慧能源一体化调控平台（综合概述）

**用户要什么**：一个屏幕监、管、控全院；电耗/空调/热水/电梯/照明/配电间全面统计分析；碳排分析；用能/单耗/碳排分析 + **能源自审报告自动生成**。

**现在有什么**：
- 大屏框架已落地：17 框 HUD 由 schema `hudLayout` 驱动、8 场景切换子系统、header 8 tab 切场景（GK-06/07/18）。
- 后端 `/regulation/overview`、`/energy/summary`、`/energy/trend`、`/bigscreen/panels` 均返回聚合数据（含 `carbon_kg`、`cost`）。
- 但全部为**合成值**（电价 0.8 元/kWh、碳因子 0.581 kg/kWh，`synthetic.aggregate.ts:9-10`）。

**差在哪**：① 无真实数据源；② **无单耗分析端点**；③ **无能源自审报告生成**（仅有历史 CSV 导出）；④ 碳因子为示范值。

**最关键 3 个补齐动作**：
1. 打通真实数据源（设 `DATA_SOURCE_MODE=real` + 配置适配器），让 overview 显示真值（SS-01/SS-02/SS-07）。
2. 新增单耗分析端点与基准主数据（床位/面积）（SS-05）。
3. 建设能源自审报告生成引擎 + 模板（SS-06）。

---

## 2. 设备生命周期管理系统（设备生命）

**用户要什么**：设备档案（技术参数/生产/启用时间/数量/场地/厂家）、运行数据（工作时间/故障次数/维修记录）、维护保养（维修记录/保养计划/维护费用）。

**现在有什么**：
- `/devices` 完整 CRUD + 设备类型/品牌台账（`device-types/brands`）。
- 合成 `lifecycle_equipment`（健康分/安装日期/下次保养）、`lifecycle_maintenance`（计划/状态）、`/work-orders` 工单 CRUD。

**差在哪**：① 档案字段不全（缺厂家/生产日期等深度字段）；② 无 per-device 工作时间/故障累计模型；③ 维保费用、计划引擎弱（合成）。

**最关键 3 个补齐动作**：
1. 补全设备档案字段并对接真实台账（SS-08）。
2. 建立设备运行台账模型（工作时间/故障次数）（SS-09）。
3. 维保计划+费用落到 `work-orders` 并接入真维保流（SS-10）。

---

## 3. 空调集中控制调度系统（空调）

**用户要什么**：按建筑/部门·楼栋/楼层/房间批量远程操作；每台空调电流/功率/时间/电量；每层汇总；内机信息+运行参数；策略组（制冷下限/制热上限/开关机时间，绑定内机）。

**现在有什么**：
- `RemoteControlDialog.vue` 基础版：开关/模式/温度/风速 + 控制组批量。
- `/hvac/status|control` + `/control-groups`；后端 `hvacStatus.perFloor` 已算每层汇总（`synthetic.aggregate.ts:67-80`）。
- GK-23（空调/照明控制深化）进行中。

**差在哪**：① 楼层/房间维度批量 + 节能命令未深化；② 缺电流/累计电量字段；③ **策略组/定时/限值引擎完全缺失**（仅通用群组）；④ 数据合成。

**最关键 3 个补齐动作**：
1. 深化批量远程操作（楼栋/楼层/房间 + 节能命令），收口 GK-23（SS-11）。
2. 补齐每台/每层指标字段与 UI（SS-12/SS-13/SS-14）。
3. 新建策略组引擎（限值/定时/绑定内机）（SS-15）。

---

## 4. 智慧照明管理系统（照明）

**用户要什么**：建筑/部门集中控制 + 联动/定时/远程；楼栋能耗统计；特定场地智能感应。

**现在有什么**：`/lighting/status|control` 通用单动作下发；合成 `lightingStatus.energy_today_kwh`（`synthetic.aggregate.ts:104-124`）。

**差在哪**：① **无联动/定时引擎**（核心缺口）；② `CATEGORY_DEFS` 无照明设备类别，台账无法挂载；③ 智能感应无任何接口/逻辑。

**最关键 3 个补齐动作**：
1. 补照明设备类别与主数据，建立楼栋能耗统计 UI（SS-17）。
2. 新建联动/定时控制引擎（SS-16）。
3. 接入智能感应硬件与逻辑（SS-18）。

---

## 5. 医院电力监控系统（电力）

**用户要什么**：单个电表每日用电量统计；某时段某区域/组织用电明细查询；区域按能耗性质年/月统计。

**现在有什么**：`/power/status` 返回进线/相电压/电流/功率因数/THD 合成值（`synthetic.aggregate.ts:126-154`）；`/history` 可按设备/子系统/时间查询。

**差在哪**：① **无电表台账与单表日用量时序**；② 非"按组织/区域"口径；③ 无年/月、按能耗性质聚合。

**最关键 3 个补齐动作**：
1. 建立电表主数据 + 单表日用量时序采集（SS-19）。
2. 按区域/组织口径的用电明细查询（SS-20）。
3. 年/月、按能耗性质的聚合统计（SS-21）。

---

## 6. 热水集中控制调度系统（热水）

**用户要什么**：热水设备数据接口对接 + 集中控制调度 + 数据呈现。

**现在有什么**：`/hotwater/status|control` 返回合成状态（`heat_pump_water` 类别，`synthetic.aggregate.ts:156-177`）。

**差在哪**：**真实设备数据接口未对接**，仅合成；集中调度 UI 待建。

**最关键 3 个补齐动作**：
1. 对接真实热水设备采集接口（外部依赖）（SS-22）。
2. 集中控制调度 UI 与策略。
3. 数据呈现面板（水温/水箱/COP/压缩机功率）。

---

## 7. 电梯节能管理系统（电梯）

**用户要什么**：电梯储能回馈装置数据接口对接 + 统一管理 + 数据呈现。

**现在有什么**：`/elevator/status|control` 返回合成状态（运行次数/能耗/再生能源，按楼层估算，`synthetic.aggregate.ts:179-203`）。

**差在哪**：① **真实储能回馈装置未对接**；② `CATEGORY_DEFS` 无电梯设备类别，无法挂载真实台账；③ 无统一管理 UI。

**最关键 3 个补齐动作**：
1. 补电梯设备类别与主数据（SS-23）。
2. 对接真实储能回馈装置采集接口（外部依赖）。
3. 统一管理 + 数据呈现（再生能源/待机能耗等）。

---

## 总览：跨子系统共性差距
- **真实数据为零**：`RealConnector` 默认 Mock，适配器环境变量全空 → 全平台"已实现"在生产意义下为 0。
- **设备主数据不全**：电梯/照明缺类别定义。
- **高级引擎缺失**：策略组、定时联动、智能感应、自审报告、单耗分析、年/月统计均为新建。
- **合规口径**：碳因子/电价为示范硬编码值，需配置化并在真数据接入后重置。
